## Codebase Patterns
- Database models go in `database/src/models/<name>.rs`, registered in `database/src/models/mod.rs`
- Database queries go in `database/src/queries/<name>.rs`, registered in `database/src/queries/mod.rs`
- Both mod.rs files use `pub mod` + `pub use` glob re-exports
- Query functions follow pattern: `#[instrument(skip(pool))]`, return `Result<T>`, use `anyhow::Context` with `.map_err(|e| Error::DatabaseError(e.to_string()))`
- Tests use `setup_test_db()` with `:memory:` SQLite pool + `sqlx::migrate!().run(&pool)`
- Migrations are numbered sequentially (currently at 017)
- argon2 v0.5 uses `password_hash` crate traits: `PasswordHasher`, `PasswordVerifier`, `PasswordHash`
- tower-sessions version compatibility: use `tower-sessions = "0.14"` with `tower-sessions-sqlx-store = "0.15"` — they share `tower-sessions-core 0.14.0`. Other version combos cause `SessionStore` trait mismatch.
- `ExpiredDeletion` trait must be imported (`use tower_sessions::ExpiredDeletion`) to call `continuously_delete_expired()` on session stores
- AppError variants: `DatabaseError`, `TemplateError`, `NotFound`, `ValidationError`, `InternalError` (defined in `server/src/routes/ui/mod.rs`)
- Session key constant pattern: `const USER_ID_KEY: &str = "user_id"` in auth.rs for session get/insert
- Auth middleware pattern: use `axum::middleware::from_fn` with `Session` extractor. Layer must be placed INSIDE (added before) session layer so Session extractor works. Order: `routes.layer(auth_middleware).layer(session_layer)`.
- Exempt path checking in middleware: check `request.uri().path()` before session extraction for performance on static assets
- WebSocket detection in middleware: check `request.headers().get("upgrade")` for "websocket" value (case-insensitive)
- Encryption uses `OnceLock<[u8; 32]>` global for the key — initialized once at startup via `encryption::init_encryption_key()`, then `encryption::is_initialized()` / `encrypt()` / `decrypt()` used in query layer
- Credential queries transparently encrypt/decrypt using the global key; if key not initialized, stores plaintext with `encrypted = false` flag
- AES-256-GCM format: base64(nonce_12bytes || ciphertext || auth_tag) — nonce is random per encryption

## 2026-02-28 - US-003
- Implemented authentication middleware to protect all routes
- Files modified:
  - `server/src/routes/ui/auth.rs` - Added `require_auth` middleware function using `axum::middleware::from_fn`
  - `server/src/main.rs` - Applied auth middleware layer between routes and session layer
- Implementation details:
  - Middleware checks `Session` for `user_id` key; if present, request proceeds
  - Exempt routes: `/auth/login`, `/auth/logout`, `/static/*`, `/api/v1/health`
  - Unauthenticated WebSocket upgrades → 401 (checks `Upgrade: websocket` header)
  - Unauthenticated API requests (`/api/*`) → 401 JSON `{"error": "Authentication required"}`
  - Unauthenticated browser requests → 302 redirect to `/auth/login`
- **Learnings for future iterations:**
  - Axum middleware layer ordering is critical: `.layer(auth).layer(session)` means session processes FIRST (outermost), then auth runs with session available
  - `Session` implements `FromRequestParts` so it can be used as an extractor parameter in `from_fn` middleware
  - `is_some_and()` is a clean Rust idiom for checking Option contents with a predicate
  - The health endpoint is at `/api/v1/health` (nested under `/api` then `/v1`), not `/api/health`
